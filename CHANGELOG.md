# Changelog

## Unreleased

* **Kernel** (`@pylos/core`): a provider stream that returns no reply no longer commits an empty assistant turn — the lane fails the turn with "the model returned no reply — the turn was not recorded; send again to retry", leaves the user's question as the newest turn, and a resend retries cleanly. The OpenAI-compatible gateway reports the same failure instead of an empty completion.
* **App, kernel** (`@pylos/core`, `apps/app`): a passing chain verification is now recorded in the vault (migration `029-chain-verified`), so the chain figure lights after you verify and honestly returns to `—` when new turns arrive; thread stats carry `verifiedTo` once a verify has passed. A checkpoint the writer left on append is not, and never was, a claim that anything was verified.
* **Kernel** (`@pylos/core`): packet verification now attributes recovery markers to the compiler's own page inserts in the packet header, so a turn whose window quotes an earlier `⟦recovered #n⟧` block — or a user who types one — no longer fails `verify` on an otherwise exact archive.
* **Deterministic bench identity** (`@pylos/core`, `bench/`): `threads.create` takes an optional `provenance` (`id`, `createdAt`), and atoms sharing a validity sequence now order by insertion rather than by their random id. Two runs of `bench million` with the same seed produce the same head hash, packet digests, ledger count and token figures; only wall-clock fields and the WAL-sensitive `archiveBytes` still move.
* **core**: lexical search takes its top-k from the FTS index and proves the page equals the unbounded query before returning it, instead of joining and sorting every match — the million-turn bench's per-turn cost stops growing with the archive (30,000 turns, seed 6: 643s → 69s, identical results).
* **Landing page** — the nav capsule says whose number it is (`OUR PROOF RUN 1,000,000 turns · chain ✓`) with a tooltip pointing at `bench/results/million-6.md`, so a first-time reader cannot mistake it for a stat about their own session.
* **Landing page** — plain words come first and the term follows: the six-noun glossary strip is gone, each term is glossed at first use with its full definition on hover, the aperture wakes with *Waking the million-turn archive…* instead of a wall of zeros, and the console's cards say `⟦brought back turn #345 · by its number⟧` with the route name kept in the receipt line.
* **Landing page** — the story's receipt row names each hash and links the artifact it can be checked against.
* **App** — the model chip tells the truth at rest: a model whose provider holds no credentials reads `· not connected`, and a tap opens the connect options; the failure no longer waits for a send.
* **App** — the four evidence figures explain themselves in plain sentences (hover and aria), including the empty-thread states where `—` used to stand alone; the proof tour names all five of its acts and drops an internal codename.
* **Retained-byte closure** (`@pylos/core`, `@pylos/protocol`): every retained byte now falls into one of four exclusive states, oversized recent episodes get explicit receipts, and attachments are hash-addressed spans reachable through a bounded tail route. Kernel tests and the natural bench's reachability-receipt observation are the evidence; the million-turn funeral had no packet rows, so it does not show receipt survival.
* **Coverage and remembered-claim gates** (`@pylos/core`, `@pylos/server`): collection questions now carry packet and answer coverage receipts bound to a typed count rather than an arbitrary span, and remembered claims are checked against a current witness before a stream releases. Tests cover both receipts and revalidation; this is not an entailment or fact-checking claim.
* **Address graph and optional semantic routing** (`@pylos/core`): grounded query routes persist until an explicit deletion, revision, hash failure, or invalidation, and the optional local `sqlite-vec`/`sqlite-lembed` route proposes addresses only. The natural bench observed semantic receipt availability on 13/13 authored probes and an exact target address on 6/13, with the sqlite-vec runtime itself reported implemented `yes`/tested `no` (the runtime exists in-tree with kernel tests, but this bench invokes no semantic runtime directly); a separate arm64 macOS preflight passed one runtime/KNN smoke path. Neither result licenses semantic recall or precision.
* **Proof thread** (`@pylos/core`, `@pylos/server`, `@pylos/app`): an empty thread can open a deterministic, receipt-backed tour of correction, partial coverage, invalidation, attachment-tail paging, and the memory gate, with a read-only summary that survives reload and each source, receipt, route, and attachment span opening as a bounded inline evidence view. It is a product demonstration, not a benchmark.
* **Bundle compatibility** (`@pylos/core`): the default writer is now a stream-native framed v2 bundle; the legacy v1 ZIP writer is still available explicitly and v1 bundles still read. `funeral-6.md` + `funeral-6.json` (schema `pylos.bench.laptop-funeral.v3`) record an exact 1,000,000-episode source and restore, identical head `602ce624efd20b1bb9d2354a552351ec062e1e4b87de558468dd0890429c27da`, a 434,722,285-byte bundle, and exact turn-730,000 paging, with packet, answer, coverage, address, and alias receipt counts all zero and RSS snapshots reported, not treated, as a bound.

## 1.3.0 — 2026-08-23

* **Proofs** (`bench/results/`): `million-5.md`/`.json` — kernel 1.3.0 (`million-4.md` is the prior kernel 1.2.0 run), 1,000,000 turns, hard cap 8,192 held (max 8,080), 2,000/2,000 facts, 200/200 quotes, 50/50 numbers, 10,000/10,000 turn-number probes, 2,000/2,000 name-free memories, authority 200/200, and the new family: **2,000/2,000** questions carrying a conversational cue and two words the corpus cannot contain left exactly one unresolved `fault` record and the `⟨pylos fault⟩` notice, none of their own routes resolved, and **0** of the addressable probes in every other family faulted; ledger conserved, chain verified; results schema `pylos.bench.million.v3`.
* **A miss is a receipt** (`@pylos/core`, `@pylos/protocol`): when a question refers back to the conversation — *what did I decide…*, *what was my…*, *remember the…* — and none of its own routes reach anything (no turn number, no recorded name, no search hit), the kernel now records a `fault` page and tells the model so, in one line: `⟨pylos fault⟩ Nothing in this question matched the archive's index … That says nothing about whether the archive holds the answer …` — call `recall` with other words, or say you could not find it; answer a question about the world normally. Before this, an unrouted question left `pages: []` and the model was free to infer the archive had been searched for it. The fault is decided over the question's own routes only (a route that fired on the previous reply's names answers the model's sentence, not the user's question), is never raised when a turn reference was already in view, when a turn in view carries every searchable term of the question, or when the view holds the whole archive, costs no page of `P_max`, is priced at its rendered cost, and is a resident span the X-ray can show. `PageTrigger` gains `fault` (KERNEL A11.1). The cue list is a heuristic and is stated as unmeasured; the bench measures only that a routing miss with a cue leaves exactly one receipt and that no addressable probe faults.
* **The thread remembers how it answered** (`@pylos/core`, `@pylos/protocol`): a question that was once answered from the archive leaves the question, the reply, and a packet recording which turns were recovered to answer it. When a later paraphrase reaches that question or reply by lexical search — in the user's or the model's own words, which are rarely the original turn's — the pager follows the receipt back to the exact source and serves it as a `path` page, `⟦recovered #450 · user · via #61234⟧`: the locator of each resolved record only, in a stated priority, ledger records only when their name is the question's, roles `user`/`tool`/`attachment` only, at most two per hit, depth one, inside the same `P_max`. An address, not an authority: the source keeps its role and its `epistemic`; nothing is written to make it work, so it is conserved by export and closed by forgetting. `PageTrigger` gains `path`; a `recall` keeps a path record as `path` (KERNEL A11.2). Measured by kernel tests only this release.
* **Turn numbers as the interface prints them; the neighbour follows the speaker** (`@pylos/core`): `turn 483,112` and `#483,112` now parse; *what did I say on turn 450?* about an assistant turn pages #450 exactly and, beside it, the nearest preceding user turn — the question that reply answered — instead of the turn after; *what did you say to turn 450?* about a user turn pages the reply; tool results, attachments, system notes and handoffs are stepped over, and `+1` remains the default (KERNEL A11.3). `sequenceRefs` moved to `@pylos/core/pure`, so the landing page's console and the pager parse an address with one function.
* **Import restores the atom name index** (`@pylos/core`): `importBundle` wrote atoms without the `atom_name` rows that atom routing and the historical route read, so an imported thread certified its frontier but could not route a question naming a subject when the frontier was over capacity. Import now indexes every restored atom, and migration `010-atom-name-rebuild` indexes, once on first open, any thread that holds atoms and no index rows — a vault imported under 1.1 or 1.2 is repaired the same way (KERNEL A11.4).
* **The view is the answer** (`@pylos/core`): when the lexical search matched only turns the packet already held, an unresolved `search` receipt was still written and rendered `⟨UNKNOWN: no exact material found for …⟩` — telling the model the material was missing while it sat two lines below. No receipt and no UNKNOWN line are written in that case; a loose match still writes the receipt and can still fault.
* **The question is never its own witness** (`@pylos/core`): the strict AND pass of the lexical route matched the question's own episode (it is in the index before compile), so the broader OR pass never ran and a natural question — *What did Virgil say about the glass bridge?* — faulted while *What Virgil glass bridge?* recovered the line. `episodes.search` now excludes the asking turn inside the SQL for both the compile-time route and a `recall` issued during the turn; regression test "the question's own turn is never its own search hit". Bench numbers unaffected (the bench compiles without a question seq).
* **`pylos serve` stays up** (`@pylos/core` CLI): `serve` returned as soon as the server was listening and the process exited; it now runs until SIGINT/SIGTERM and stops cleanly. The "not available" error now says to run `bun install` in a checkout.
* **`--home` owns its credentials** (`@pylos/server`): `pylos serve --home <dir>` read `~/.pylos/auth.json` and could spend the machine's xAI session from a scratch profile; the auth file is now `<home>/auth.json` unless `PYLOS_AUTH_PATH` is set.
* **Handoff when the next turn runs** (`@pylos/server`, `@pylos/app`): switching the model chip appended *"Grok continued from the same thread"* at once — even in an archive where no model had spoken. The handoff episode is now appended by the turn lane immediately before a turn whose model differs from the last assistant's; `POST /threads/:id/handoff` refuses with `409 no_speaker` on an empty thread and is a no-op when nothing changed.
* **`no_provider` is 409, not 401** (`@pylos/server`): sending a turn with no connected provider is not a session failure.
* **Removed** (`@pylos/protocol`, `@pylos/server`): `TurnRequest.attachmentSeqs`, which was accepted and ignored — an uploaded attachment already enters the archive through `/attach` and the recent window. A server test pins that behaviour.
* **Design** (`docs/DESIGN.md`, `apps/web`, `apps/app`): kiln and bone — one fired colour, Instrument Serif and Courier Prime, public-domain engravings screened to two colours (Doré's Empyrean and Ninth Heaven, the Flammarion engraving, the Confusion of Tongues, the Mnemosyne plate). Newsreader, Geist Mono on the page and the `@fontsource` packages are retired.
* **Landing page** (`apps/web`): rebuilt in that system. The story — the live-bench trap in four beats, plain words — follows the hero; the proof is a chart drawn from `public/bench/series.json` (derived from `bench/results/million-5.json` at build): the archive climbing to 1.05 GB against a flat view under the 8,192 cap, and beneath it what can still be brought back exactly at each checkpoint — Pylos 100% at every one, the rolling summary 26%, BM25 6% at 1,000,000. The console answers a question about the world with `⟦not a memory⟧` instead of a fault (the same cue gate as KERNEL A11.1), and `remember: …` appends the visitor's own turn at #1,000,001 to the in-browser archive so it can be asked for back. `final.json` no longer carries a date or a runtime, so a build leaves the tree clean. Install names only the platforms the release builds.
* **The presence** (`@pylos/app`): the app is no longer a transcript. A procedural halftone ring — angle is position in the thread — breathes at rest, fills while the packet is built and lights the position of each recovered turn; one exchange is on screen; the archive (the virtualised transcript and the rail) is a drawer opened with `earlier` or ↑; the evidence figures sit around the ring and open the X-ray; the model menu lists connected providers first and `connect ▸` for the rest; sign-in and connect share one screen and a device-code poll survives a transient error.
* **Release** (`.github/workflows`): release.yml runs the same gates as CI (typecheck, test, lint, secret scan, web build, app and web tests) before packaging; CI fails if a build changes a tracked file.
* **Team** (`.claude/agents/beta.md`, `CLAUDE.md`): a cold beta-tester agent that meets the product without its vocabulary and reports before a public surface is called done.
* **Server** (`@pylos/server`): a turn's per-thread lane is claimed at request arrival, not after the body is read and the model resolved — two turns sent a tick apart could reach the lane out of order and commit `question B, answer A, question A, answer B`. `Kernel.enterTurn` claims synchronously; the gateway claims as soon as the thread is known; a request refused before the turn starts gives the lane back; the thread's remembered model and budget are written when the turn takes the lane, so a refused or abandoned turn no longer changes them. A test reproduces the old interleaving and passes only with the fix.
* **Web app** (`@pylos/app`): a fault the model's own search went on to answer reads `↺ page fault · recovered one earlier moment · recall`; a path recovery reads `· by way of turn 61,234`; a fault nothing answered writes no recovery line — the X-ray's *Pages served* lists it as `fault · <question> · no route` and the reply says so. The evidence bar's `recovered` counts resolved pages only.
* **Web**: the console's miss card is now `⟦page fault · no route fired⟧`, with the app's behaviour stated beside it; turn numbers with thousands separators are accepted.
* **Bench**: results schema `pylos.bench.million.v3` adds a `faults` family — 20 questions per checkpoint carrying a conversational cue and two words the corpus cannot contain; passes only if exactly one unresolved `fault` record and the notice are in the packet, none of the question's own routes resolved, and no other family's probe faulted. `--rerender` still renders v2 artifacts.

## 1.2.0 — 2026-08-22

* **Proofs** (`bench/results/`): `million-3.md`/`.json` — kernel 1.2.0, 1,000,000 turns, hard cap 8,192 held (max 8,080), 2,000/2,000 facts, 200/200 quotes, 50/50 numbers, 10,000/10,000 turn-number probes, 2,000/2,000 name-free memories, authority 200/200, routing precision 1.00, ledger conserved, chain verified — the same numbers as `million-2` on the support-aware kernel.
* **Presence is not support** (`@pylos/core`, `@pylos/protocol`): every resident span now says what it is allowed to support, and routing, the numeric presence test and the check round read only the supported ones. The turn you just sent is its own span, rendered once at the end of the packet and outside the recent window, so a leading question — *"was the contract 48,250 USD?"* — no longer suppresses the page that answers it; the exact turn comes back before the model replies rather than after. Capsule prose no longer stands in for the value it summarized, and a figure that is resident only because the model said it earlier is checked against the archive like any other unsupported claim. `ResidentItem` gains `epistemic`; a ledger route whose every locator is already in the view records nothing instead of `UNKNOWN`.
* **The user's word first** (`@pylos/core`): the rule atomizer now runs over the user's turn *before* the packet is compiled, not after the reply. A correction made this turn — *"I moved to Porto"* — is a certificate in the very first request, with the old value marked historical, instead of arriving as one more recent line. If the provider then fails, the user's atom stands: they said it, whether or not a model answered.
* **Bounded, receipted rounds** (`@pylos/core`, `@pylos/protocol`): recall results and the check prompt used to be appended to a request without a cap. Every provider request of a turn is now measured by the kernel's own count and kept within the same budget, displacing the oldest recent spans (recoverable by sequence) when it must, and each one is recorded in `Packet.rounds` with its message digest, token count, pages served, response digest, usage and status — ordinal 0 being the compiled packet. Usage on the episode is the turn's, summed across rounds, and `meta.roundsDigest` — one hash over everything the model was shown — is covered by the hash chain, along with `packetId` and `check`. Vaults gain a `packet.rounds` column; episodes written before this release hash exactly as they did and still verify.
* **Check status** (`@pylos/core`, `@pylos/protocol`): `meta.check` now carries `status` — `revised`, `confirmed`, `none` or `check-failed` — in place of the `revised` flag, and is written on every turn the check ran, so "there was nothing to check" is a receipt rather than a silence. When the check round cannot be completed the draft is still kept, and now says so in one kernel line: *⟨pylos: the archive could not be re-read for: … — treat these values as unverified⟩*.
* **Authority repaired by replay** (`@pylos/core`): migration 005 read every pre-existing atom as the user's, but v1.0 atomized assistant turns too — so an assistant's claim could hold a slot against the user's own word. On first open, a vault showing that tell rebuilds its atoms from the exact episodes under the current rules (`008-authority-replay`), keeping pins by key and leaving capsules and ledger rows alone. It costs one pass over the archive, once; vaults without the tell pay a single indexed query.
* **Kernel** (`@pylos/core`): forgetting is complete. `forget` no longer stops at the episode — the capsules that quoted it have their text re-derived over the surviving source, the packets that could still be carrying it lose their `messages` (their digest, resident set and pages stay, so the X-ray labels them reconstructed), and an attachment's bytes are deleted from `objects/` once no surviving episode references them. An assistant turn that restated the material is still never removed on a guess: the tombstone now lists those turns as `echoes`, so the interface can ask.
* **Kernel** (`@pylos/core`): forgetting is chain-bound. Each removal appends a `system` episode, `⟦removed #n · <tombstone>⟧`, and `verify()` requires every episode marked removed to have a tombstone and that later record — so setting `removed` by hand in the database now fails verification instead of skipping the content-hash check. Vault migration 008 adds `tombstone.removal_seq` and `tombstone.echoes`; removals recorded before this release are marked legacy and still verify.
* **Export** (`@pylos/core`): a `.pylos` bundle carries the attachments its own episodes reach, not every object in the profile — exporting one thread no longer ships another thread's files, and a partial export ships only what its range reaches.
* **Import** (`@pylos/core`): `packets.jsonl` is restored instead of discarded, so the X-ray survives a Laptop Funeral: an imported thread still shows what each turn was compiled from. Import checks the restored packet count against the manifest and refuses on disagreement.
* **Kernel** (`@pylos/core/pure`): the deterministic bench corpus moved into the browser-safe half as `createCorpus(seed, n)` — `episodeAt(seq)` (O(1), exact), the planted manifest, and the trap constants — so the bench and the landing page generate the same thread from one generator instead of two. Byte-identical to the generator it replaces for the same seed, including the manifest digest the results files record; `ftsTerms` moved to `pure` with it, since the same tokenizer now decides what the vault searches for and what a browser can search for.
* **Server** (`@pylos/server`): turns on one thread now run one after another. Two tabs — or a tab and the gateway — could interleave a turn's two transactions and commit `user A, user B, assistant B, assistant A`, an order that never happened. A second turn is queued rather than refused, up to eight deep per thread (a ninth answers `429 thread_busy`), and a queued turn that its client abandons lets go at once instead of holding a hosted vault open. Different threads are untouched, and a client that leaves mid-turn no longer releases the thread before the kernel's transactions have committed.
* **Server** (`@pylos/server`): the OpenAI-compatible gateway no longer concatenates a retracted draft with the answer that replaced it. A non-streaming completion carries only the committed text — the reissued answer, or the kept draft with the kernel's unverified line when the check could not be run. A stream cannot take words back, so it says so: one chunk with an empty delta and `x_pylos: {event:"check", names, retract:true}`, then the replacement deltas. Clients that ignore `x_pylos` must not treat the stream as append-only once that chunk has appeared.
* **Server** (`@pylos/server`): `POST /api/threads/:id/forget` now reports what the removal did — `removalSeq`, the `echoes` the kernel named rather than guessed at, and how many capsules, packets and attachment blobs it touched. Additive; `tombstoneId` is unchanged.
* **Web app** (`@pylos/app`): a checked answer now says which way it went. `↺ reopened the archive · 48250 usd` when the answer was reissued, `· answer stood` when it was confirmed, and, in oxblood, *archive could not be re-read · … — unverified* when the check round failed — on the answer in the transcript, not only while it streams. Forgetting a turn now offers the replies that quoted it: *two replies quoted it — forget those too?*, one click, same reason, never on a guess. The X-ray shows the turn's rounds — each request's tokens against the budget, pages served, status and digest — and labels every resident span with what it is allowed to support, because presence is not support; the evidence bar's view figure reads `7.9k / 8.2k · 3 rounds` when a turn cost more than one request.
* **Web**: the landing page gained **the impossible thread** — a console under the aperture where a visitor can put questions to the million-turn archive that was just compiled in their tab, with no sign-in and no model call. Four routes answer, and each card says which one fired and what it cost: a turn number is an address (`episodeAt(345)` is exact for any turn), the migration rule is answered by the resident certificate with the turn-1 version kept as `⟨historical⟩` beside the two answers the live bench recorded, a person's location shows the user's certificate against the assistant's `≈ … ⟨proposed by assistant #seq · unconfirmed⟩`, and a memory with no name in it is found by stemmed lexical search. The aperture now runs the bench's own corpus, so the thread on the page and the thread in `bench/results` are the same million turns; its closing act shows both receipts the kernel produces — the rule needed no page, an exact quote from turn 885,259 needed the ledger. ## 1.1.0 — 2026-08-22

* **Protocol** (`@pylos/protocol`): additive types for the above — `AtomAuthority`, the `PROPOSED` atom phase, `Me`, `TurnEvent` gains `check`, `PageTrigger` gains `sequence` and `check`. `@pylos/core/pure` renames `numbersIn`/`numericValue` to `numberOccurrences`/`parseNumberName` to match the rounding-equivalence rule they now implement. Vault migrations 005 (`atom.authority` column, existing atoms read as `user`) and 006 (`episode_fts` rebuilt with porter stemming on first open) run automatically; nothing else in the schema moves.
* **Authority** (`@pylos/core`, `@pylos/protocol`): every atom now records who asserted it — `user`, `assistant` or `model` — and an assistant's or a model extractor's claim is committed in the new `PROPOSED` phase. A proposal supersedes nothing but an earlier proposal on the same key, never joins the frontier, never enters a capsule and is never a certificate; when the user finally rules on that key, the proposal is closed with it. A model can no longer talk the archive into believing something: the worst it can do is propose, and a query about that subject sees `key ≈ value ⟨proposed by assistant #seq · unconfirmed⟩`. Tool results and attachments are data, never memory: no rule reads them, so recalled text cannot write itself into the frontier. `ThreadStats.atoms` gained `proposed`. Existing vaults migrate; their atoms read as the user's.
* **Numeric presence** (`@pylos/core`): a lost number counts as still in view only if the view holds the same number up to rendering — and, when the number carries a unit, only with the same unit. Numbers inside the kernel's own markup do not count, so a certificate's pointer `⟨#48250⟩` can no longer pass as a witness. The old 1% window let an unrelated `4950 ms` stand in for a lost `5000 ms`, and `48250 usd` for `48250 eur`; both were silent losses. Errs toward one more page, never one fewer.
* **Ask by turn number** (`@pylos/core`): "what did I say on turn 345?", "turns 10-12", "#345", "the 345th message" now page those exact turns, before any other route, at any archive size — `#345` being the sequence number on every certificate and recovery line. A bare number is still just a number, `issue #12` is somebody else's numbering, and an address is not a value: "turn 345" no longer routes on 345.
* **Search that answers questions** (`@pylos/core`): the `recall` tool always searches the archive for free text, so a model can address a memory by describing it in its own words and get exact spans back or `UNKNOWN`; at turn time the lexical route also fires when a question has two searchable terms and nothing else resolved. The index now stems ("tasted" reaches "taste") and counts three-letter words, and equal scores resolve to the newest turn. The first open of an existing vault rebuilds the search index once, which can take a while on a large archive; nothing else changes and no archive text moves.
* **The check round** (`@pylos/core`, `@pylos/protocol`): when a draft answer states something the view did not contain and the ledger knows where it is, Pylos pages the exact archive text and gives the model one round to reissue the answer against it. Recovered turns keep their role label, and the message says what that means — a user turn is the user's word, an assistant turn is a previous model's word, not confirmation — and the user's own turns are served first, so a draft cannot be confirmed by the model that wrote it. Only names the ledger recorded as dropped are checked; this is a presence check against the archive, not fact-checking. The turn emits `check` with the names and pages so the UI can drop the provisional text, and the assistant episode records `meta.check = {names, revised, draftSha256}`. If that round fails, the draft stands — a reply is never lost to the check.
* **Hosted mode** (`@pylos/server`): `pylos serve --hosted` turns the same binary into a multi-user server — one vault, one `objects/`, one `auth.json` per signed-in xAI account, under `<home>/users/<id>/`. Sign-in is the xAI device grant (`POST /api/login/xai/start` and `/poll`), which mints a 30-day bearer session; `GET /api/me` says who is signed in, `POST /api/logout` ends it, and every other `/api` and `/v1` route runs against that account's vault — including the OpenAI-compatible gateway, where the session is the API key. The turns you send are paid for with your own xAI credential, which never leaves your profile directory. Local mode is untouched: no login, no bearer, loopback only, `/api/me` returns `{hosted:false}`.
* **Serving the app** (`@pylos/server`): `--web DIR` serves the built single-page app at `/app/` with a tight content-security policy, immutable asset caching, an uncached shell and client-side routing, so one process answers both the app and the API.
* **Limits** (`@pylos/server`): a public host now refuses JSON bodies over 1 MiB and uploads over 32 MiB, caps turns at 64 a minute per account and sign-in attempts at 20 a minute per address, and streams every turn with `no-transform` and `X-Accel-Buffering: no` so a reverse proxy cannot sit on the deltas.
* **Web app** (`@pylos/app`): the one React UI moved out of the desktop shell and is now served at `/app/` by a hosted Pylos. It talks to the backend on its own origin, carries a bearer session, and opens on a sign-in screen when the server reports hosted mode — sign in with xAI, and the thread is there. The top bar became an evidence bar: archive, bytes, view against budget, ledger, recovered, models and chain state in one mono strip, each figure explained on hover, all of it still one click from the X-ray. The X-ray shows PROPOSED atoms as proposed — asserted by a model, never a certificate — with the authority behind every atom. A checked answer says so: when the draft names a lost value the provisional text is dropped and the recovered names appear above the answer that replaced it. Works on a phone.
* **Desktop**: the Tauri shell now wraps the shared app build instead of carrying its own copy of the UI; one codebase, two ways in, the same vault format.
* **Web**: the landing page leads with **Open Pylos** and keeps the download as the local-first option. The aperture no longer claims a recovery it did not make — a run whose ledger does not route to the revision says "no route fired" and records `recovered: null`, and the exhibit states what it is: the browser-safe subset of the compiler over a synthetic stream, with the million-turn bench artifact as the proof.
* **Proofs** (`bench/results/`): `million-2.md`/`.json` — kernel 1.1.0, 1,000,000 turns, hard cap 8,192 held at every checkpoint (max observed 8,069), 1,054 MiB archive, 676,593 ledger entries, 35,713 capsules; 200/200 quotes byte-exact, 50/50 numbers present with unit agreement, 2,000/2,000 revised facts current and never stale; sequence route 10,000/10,000 turn-number probes byte-exact; 2,000/2,000 name-free memories recovered by stemmed lexical search from 0 ledger rows; authority poison A 100/100, B 50/50, C 50/50, 151 atoms `PROPOSED` at 1M; ledger conserved and complete, chain verified. `million-1.md`/`.json` (kernel 1.0.0) stays as the v1.0.0 artifact.
