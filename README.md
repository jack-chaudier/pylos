<h1 align="center">PYLOS</h1>
<p align="center"><strong>The conversation that does not end.</strong><br>One thread. Every model. Nothing forgotten silently.</p>
<p align="center"><a href="https://pylos.vercel.app">pylos.vercel.app</a> · <a href="docs/VISION.md">Vision</a> · <a href="docs/KERNEL.md">Kernel</a> · <a href="docs/THEORY.md">Theory</a> · <a href="docs/DESIGN.md">Design</a> · <a href="bench/results/">Proofs</a></p>

Every chat you have ever had with a model ended the same way: the window filled, and the thing you were talking to quietly became someone who had never met you. Pylos refuses that. There is one conversation, kept exactly — every turn hashed into a chain. Whichever model is talking gets a bounded view compiled fresh from that archive, sized to its budget. Everything the view leaves out is recorded in a ledger, not silently dropped. A question that reaches back — a turn number, a name, a quote — pages the original bytes back exactly. Any model can pick the thread up mid-sentence.

> The tablets survived because the palace burned.

## Try it in 60 seconds

[**Ask the million-turn thread**](https://pylos.vercel.app/#console) in the browser — no install, no sign-in, no model call. Then:

```bash
curl -fsSL https://pylos.vercel.app/install.sh | bash
pylos serve                                          # open http://127.0.0.1:7334/app/
```

On an empty thread, open **the proof thread** — a scripted tour through a correction, a partial collection, an invalidated route, and the memory gate.

## What it does

- **Exact archive.** Every turn is hashed into a chain. Nothing is rewritten or silently pruned.
- **Bounded view.** Each provider request is compiled fresh to that model's token budget, no matter how long the thread has run.
- **Loss ledger.** What the compiled view leaves out is recorded, conserved, and checkable — not just gone.
- **Exact paging.** Turn numbers, names, and quotes page the original bytes back byte-exact. A question that reaches nothing leaves a `fault` receipt instead of silence.
- **Every model, one thread.** Grok, Claude, OpenAI, Ollama, or any OpenAI-compatible endpoint can pick up the same thread mid-conversation. Export and restore as an encrypted `.pylos` bundle. Forgetting happens only on command, and it is recorded.

## What is not claimed

Pylos does not claim to never forget — it forgets only on command, and records that it did. The model can still be wrong; the archive and the ledger describe what was said and what the view omitted, not whether it was true. A `fault` receipt means no route fired for a question, not that the archive lacks the answer. The similarity route is experimental; its numbers come from an authored 13-question set, not a recall/precision measurement on real conversation. There is no hosted service — `pylos serve --hosted` is a self-hosted, operator-managed mode; the operator supplies quotas, authentication, and monitoring. The million-turn bench is synthetic and deterministic, generated by the bench's corpus function, not real conversation. Any number not in `bench/results` is not claimed.

## The proof

Every number below points at an artifact in `bench/results/`. The deterministic bench runs with zero model calls; the same seed produces the same numbers.

| The million-turn thread exported and restored with an identical archive head; 434,722,285-byte bundle; export 13.2s, import 72.7s; turn 730,000 came back byte-exact | [`funeral-6.md`](bench/results/funeral-6.md) |
| 13 authored natural-language questions, 0 safety-oracle violations; the similarity route chose the intended source on 6/13 and a wrong one on 5/13; 0 model calls | [`natural.md`](bench/results/natural.md) |
| Live model drill: grok-4.3 answered 36/36 probes with the current rule; a chronological rolling summary at the same budget answered 5/36 | [`million-live-live-1.md`](bench/results/million-live-live-1.md) |

The rows above the last two are deterministic, kernel-only measurements that reproduce from the tree; the live drill and the handoff are recorded samples — one model, one run each — and carry no statistical claim.

Specified and tested, not yet benchmarked at scale: bounded per-round token limits (KERNEL A10.3), path-following retrieval to a paraphrase's source (A11.2), four-state reachability of every retained byte (A12), collection questions carrying a route receipt rather than an inferred total (A13), the remembered-claim gate (A14), and the address graph that keeps a resolved query's witnesses stable until explicit invalidation (A15). Each has a test suite in `packages/core/test/` and `packages/server/test/`.

## Run it

```bash
curl -fsSL https://pylos.vercel.app/install.sh | bash      # macOS (Apple silicon) · Linux (x64)
pylos serve                                                 # then open http://127.0.0.1:7334/app/
```

Or from a checkout:

```bash
bun install
bun run --cwd apps/app build && bun packages/core/src/cli.ts serve   # local, open http://127.0.0.1:7334/app/
bun run --cwd packages/server build:sidecar      # kernel + server → one binary for the Tauri sidecar
bun run --cwd apps/desktop tauri dev             # the desktop app (starts the sidecar)
bun packages/core/src/cli.ts bench million --turns 100000 --seed 1 --budget 8192
```

Sign in with xAI on first send (device sign-in, an API key, or your Grok CLI login); Anthropic and OpenAI keys and local Ollama models appear in the model chip once connected. Credentials live in `~/.pylos/auth.json` (0600) — or in `<home>/auth.json` when you run with `--home` — and never enter the vault or an export. `pylos serve --hosted` is a self-hosted, operator-managed mode; Pylos does not run a hosted service.

Release builds: `.dmg` (Apple silicon) and `.deb` (x64) from the [releases page](https://github.com/jack-chaudier/pylos/releases), with headless `pylos-{macos-arm64,linux-x64}.tar.gz`, built by `.github/workflows/release.yml`.

## Layout

```
packages/protocol   shared types + the local API contract
packages/core       the kernel (bun:sqlite) · src/pure is browser-safe and powers the landing page's thread
packages/server     local API, providers, auth custody, OpenAI-compatible gateway
apps/app            the React app — the presence, one composer (served at /app/; wrapped by the desktop shell)
apps/desktop        Tauri 2 shell
apps/web            the landing page (Vite, static, Vercel)
bench/              the million-turn bench, the live variant, and results
docs/               VISION · KERNEL (contract) · THEORY (results → mechanisms) · DESIGN · PLAN
```
